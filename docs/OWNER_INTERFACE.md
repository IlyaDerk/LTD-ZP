## Работа собственника

1. Перезагрузить таблицу и выбрать **Зарплаты → Открыть интерфейс**.
2. В sidebar задать период по дате готовности (границы включаются), сотрудника, статус и объект. При заданном периоде статьи без даты исключены; без периода видны и запланированные.
3. Нажать **Применить фильтры**. Лист «Интерфейс собственника» получает компактную копию только найденных статей, начиная со строки 11. Фильтр общий для листа; его изменение полностью заменяет прежнюю выдачу и сбрасывает выбор невыплаченных статей.
4. Отметить checkbox **Выбрать** на листе. Выбирать можно только статьи со статусом **К оплате**; исходные статьи от этого не меняются. Формулы в `H5:I5` сразу пересчитывают количество и сумму, а sidebar перечитывает выбор только по кнопке **Обновить выбор**.
5. Нажать **Подтвердить оплату** в sidebar: сервер перечитает источник и покажет количество, сумму и ID.
6. Только кнопка **Да, зафиксировать выплату** записывает «Выплачено», дату выплаты, «Обновлено» и флажок исходной статьи. Это учёт факта выплаты, не банковский перевод и не передача в кассу.

Выплаченная статья отображается с отмеченным checkbox, не учитывается в выборе и повторно не проводится. «Статьи оплаты» — единственный источник истины. Устаревшая выдача, изменённый выбор/сумма или невалидная статья требуют обновления и нового подтверждения.

## Сохранность и атомарность

- ID статьи хранится в скрытом столбце A интерфейса. При фильтрации управляемая область `A11:J` очищается и заполняется только найденными статьями подряд; строки листа физически не удаляются и не скрываются. Области K и далее не изменяются.
- Управляемые столбцы интерфейса A:J не предназначены для ручного редактирования, кроме **Выбрать**. «Статьи оплаты» остаются источником истины, а перед подтверждением ID, суммы и статусы выдачи сверяются с источником.
- В источнике меняются только четыре поля выбранных статей. Форматирование, validation, неизвестные столбцы и остальные статьи не изменяются.
- Все серверные операции расчёта, чтения/обновления интерфейса и подтверждения используют одну `ScriptLock` нового проекта.
- Простой `onEdit(e)` отбрасывает любые правки вне столбца **Выбрать** до чтения данных. Он читает только статусы и checkbox затронутых строк интерфейса: восстанавливает `TRUE` для **Выплачено**, возвращает `FALSE` для **Запланировано** и **Отменено**, а новый выбор разрешает только для **К оплате**. Сделки, справочники и «Статьи оплаты» не перечитываются; `H5:I5` обработчик не записывает.
- Запись группы выполняется одним [Sheets API spreadsheets.batchUpdate](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate): подзапросы применяются вместе либо отклоняются вместе. Устаревший preview (5 минут), повторные ID, неверные статусы и формулы в целевых полях отвергаются до записи.
- ScriptLock не блокирует ручные правки таблицы и ручной запуск кода старого standalone-проекта. У старого проекта нет активных триггеров, и запускать его параллельно с новым проектом не следует; во время подтверждения нельзя вручную редактировать источник.
- Если после записи не удалось обновить представление, ответ явно сообщает об успешной выплате и просит обновить интерфейс, а не повторять оплату.

## Миграция и триггеры

`onOpen()` — простое меню; встроенный `onEdit(e)` обслуживает только выбор в интерфейсе и не оплачивает источник. `setup()` только проверяет структуру и контейнер. Код не создаёт триггеры автоматически. Deployment не нужен.

- В старом standalone-проекте нет активных триггеров.
- Installable-триггер `handlePaymentEdit` старого проекта удалён; активных installable `handlePaymentEdit` в системе нет.
- В новом привязанном проекте активен ровно один ежедневный time-based триггер `dailySync`.
- Подтверждение выплаты выполняется только через preview и явную кнопку подтверждения в sidebar. Checkbox и встроенный `onEdit(e)` выплату не проводят.

## Сводка и обновление sidebar

Строка 4 содержит названия показателей: `B4:E4` — **Запланировано / К оплате / Выплачено / Итого**, `G4:I4` — **Найдено статей / Выбрано статей / Сумма выбранных**. Строка 5 содержит соответствующие значения: суммы в `B5:E5`, количество найденных статей в `G5`, формулу `=COUNTIFS(H11:H,TRUE,G11:G,"К оплате")` в `H5` и формулу `=SUMIFS(F11:F,H11:H,TRUE,G11:G,"К оплате")` в `I5`. Старые дубли очищаются только в `B6:B7`, `D6:D7` и `B8`. Строка заголовков таблицы остаётся строкой 10, технический столбец A скрыт.

Sidebar не выполняет фоновый polling. Сервер вызывается только при открытии, применении или сбросе фильтров, по кнопке **Обновить выбор**, при предварительной проверке и после явного подтверждения выплаты. Блок пропущенных сделок раскрывается локально и по умолчанию свёрнут.

Старый standalone не удалён и остаётся резервной копией кода, но автоматических запусков из него больше нет. Работать и подтверждать оплату нужно только через **Интерфейс собственника** нового привязанного проекта.

`.clasp.json.example` указывает на новый bound-проект. `.clasp.standalone.json.example` сохраняет только старый ID/rootDir, без credentials. Этот пример не предназначен для публикации новой bound-версии в standalone; старый код доступен в коммите `47692cd`.

## Границы приёмки

Локальные тесты проверяют фильтры, выбор и подтверждение одной/нескольких статей, атомарный отказ, устаревшие данные, повторную выплату, сохранение PAID/idempotency, пользовательских столбцов и validation. Живая проверка записи «Выплачено» разрешена **только после отдельного согласия на конкретные тестовые статьи**. Не удалять тестовые/рабочие статьи. «На кассу» и импорт из amoCRM в этот этап не входят.
