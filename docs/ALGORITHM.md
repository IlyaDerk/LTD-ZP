# Алгоритм MVP

1. Все обязательные листы читаются полностью, строка заголовков находится по именам в первых 20 строках.
2. Визуализатор `Нет` задаёт два акта; ФИО — три; пустое значение даёт `NEEDS_REVIEW`.
3. Активные правила и виды статей определяют статьи и слот получателя. Коллажи при двух актах не добавляют статью.
4. Получатель сопоставляется по нормализованному ФИО и периоду на дату готовности либо дату запуска для `PLANNED`.
5. Модель каждого получателя отдельно выбирает матрицу: Москва — стоимость проекта × процент; Тамбов — метраж × ставка работы/пакета. Бонус всегда принадлежит инженеру и использует полную стоимость проекта.
6. Условие готовности задаёт дату и статус `TO_PAY`; без даты статья остаётся `PLANNED`.
7. Фонд округляется до рубля. При делении остаток после округления вниз остальных частей получает первая статья.
8. Слияние идёт по детерминированному ключу. Неизменённая строка не записывается и её `Обновлено` не меняется; `PAID`/`CANCELLED` сохраняются без изменений.
9. Установка checkbox разрешена только одиночным edit для `TO_PAY`; успешная операция атомарно фиксирует `PAID` и дату выплаты под общей script lock.
