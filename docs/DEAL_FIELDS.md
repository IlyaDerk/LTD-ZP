# Поля сделки для расчёта

Расчёт использует поля листа `Выгрузка сделок` по следующим правилам. CRM-статус сделки не читается и не управляет готовностью статьи или оплатой.

## Обязательные для каждой сделки

- `ID сделки` — непустой стабильный идентификатор. Пустой ID отклоняет только эту сделку.
- `Инженер-дизайнер` — однозначное ФИО действующего сотрудника из справочника.
- `Визуализатор / Нет` — `Нет` для схемы с двумя актами либо однозначное ФИО визуализатора для схемы с тремя актами.
- `Стоимость дизайн-проекта` — положительное число. Оно необходимо для обязательной статьи бонуса за ремонт и для всех статей сотрудников с моделью `Москва`.

Для каждого выбранного исполнителя в справочнике обязательны непустой `ID сотрудника`, поддерживаемая модель мотивации (`Москва` или `Тамбов`), грейд, единственная действующая запись и единственная подходящая положительная ставка. Ошибка справочника отклоняет только затронутую сделку.

## Условно обязательные

- `Метраж после замера` — положительное число для любой неремонтной статьи получателя с моделью `Тамбов`, включая развёртки.
- `Пакет дизайна` — должен однозначно находить ставку в матрице Тамбова, когда правило использует пакет как вид работы: двухактная схема, схема из трёх актов с одним исполнителем и инженерная часть разделённой схемы для инженера модели `Тамбов`.
- `Тип визуализации` — обязателен при трёх актах и разных исполнителях; поддерживаются фактически реализованные варианты `3D-визуализация` и `Коллажи`.
- `Развёртки` — необязательный признак. Значение `Да` или `Есть` включает отдельную статью; тогда инженер должен иметь модель `Тамбов`, а метраж и ставка `Развёртки` должны быть корректны.
- ФИО визуализатора — обязательно только для трёхактной схемы и должно соответствовать ровно одному действующему сотруднику.

## Необязательные для расчёта суммы

- `Дата выполнения Акта №1`, `Дата выполнения Акта №2`, `Дата выполнения Акта №3`, `Дата подписания ремонта` могут быть пустыми. Пустая дата не отклоняет сделку: соответствующая статья получает статус `Запланировано`. При появлении требуемой даты статус становится `К оплате`.
- В двухактной схеме статья `Акт 1` использует дату акта 1, а `Акт 2` — дату акта 2.
- В любой трёхактной схеме первая/инженерная статья получает более позднюю из дат актов 1 и 2, но только когда заполнены обе даты. Вторая/визуальная статья использует дату акта 3.
- Статья развёрток использует дату акта 1, статья бонуса за ремонт — дату подписания ремонта.
- `ID объекта` и `Название сделки` не участвуют в формуле суммы. Название используется для интерфейса и диагностики.
- CRM-статус, стадия воронки и факт нажатия checkbox не являются входами расчёта. Оплата управляется отдельно через sidebar.

Неподходящее или пустое условно обязательное поле добавляет причину в диагностику конкретной сделки. Остальные сделки продолжают рассчитываться.
