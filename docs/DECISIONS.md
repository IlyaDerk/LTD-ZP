# Решения

1. Источник ставок, долей, сотрудников и активных видов выплат — только актуальные листы книги; fixtures копируют подтверждённую форму матриц, но не участвуют в production-расчёте.
2. Уникальность статьи: `ID сделки + ID правила + Код статьи + слот получателя`. ID сотрудника можно исправить без создания дубля.
3. Готовая статья ищет запись сотрудника и ставку на дату готовности; `PLANNED` — на дату запуска. Ноль или несколько совпадений дают прикладной `NEEDS_REVIEW`.
4. Сначала округляется фонд сотрудника. В группе долей все части, кроме первой, округляются вниз; первая получает остаток.
5. `PAID` и `CANCELLED` не перезаписываются. Автоматические корректировки и частичная оплата исключены.
6. `setup()` имеет единственное допустимое структурное изменение: добавить отсутствующий в текущей книге checkbox `Оплатить`; существующие неоднозначные столбцы не удаляются.
7. Публикация в Apps Script отложена до отдельного разрешения владельца.
